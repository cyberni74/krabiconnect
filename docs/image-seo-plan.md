# Image SEO Plan – Krabi Secret Islands

Research + inventory + rename/alt plan by the **image-seo** agent (2026-10-05). The **google-seo** agent decides and applies; no code was changed.
Machine-readable mapping: `docs/image-seo-plan.json` (same rows as the table in §2).

## 1. Rules (derived from research)

1. **Alt text is the main signal; file name is a light hint.** Google uses alt text, file name, the page title and the text around the image together – the alt attribute is the most important metadata field, the file name only gives "very light clues". Alt text must describe *this* picture, in context, without keyword stuffing. ([Google Image SEO best practices](https://developers.google.com/search/docs/appearance/google-images))
2. **Alt text in the page language.** The dictionary system already translates every `{de, en}` string to ZH/KO/JA (`src/components/secret-islands/i18n/*.ts`, keyed by the German text) → every new/changed DE alt needs a matching entry in `zh.ts`, `ko.ts`, `ja.ts` (run `extract.ts --missing`). Guide articles are DE/EN only.
3. **One file name per image, in German, shared by all languages.** Google's own advice: don't translate the file name when the *same* image is used on several language versions – keep one URL, easier crawling/indexing ([Search Engine Roundtable – Mueller](https://www.seroundtable.com/google-do-not-translate-image-file-names-28903.html)). Translate file names only for images that exist solely on one language version. The site is DE-first (`x-default` = DE) → German names; place names stay in their search form (`hong-island`, `maya-bay`, `james-bond-island`, `railay-beach`).
4. **Name pattern: `<place>-<activity/subject>-<detail>.webp`**, lower-case ASCII, hyphens, 3–6 words, umlauts transliterated (ä→ae, ö→oe, ü→ue, ß→ss). Include *krabi* (or *phang-nga* / *phi-phi* / *andamanensee* when that is the real place). Brand only where the brand is the subject (logo, own boat). **Avoid:** dates, hashes (`hf_2026…`), camera names, `-1/-2` numbering when the pictures differ, the same keyword chain on many files, `bild`/`foto` filler.
5. **The picture must match its name, alt and caption.** Never reuse one AI scene under another island's name (today: Koh Poda shown as "Koh Nok", Maya Bay as "Koh Kudu"/"Koh Lao Lading", Hong as "Phi Phi", Koh Roi as "Railay", James Bond as "Koh Pakbia"). A wrong alt is worse than a generic one – it can rank the image for the wrong place and misleads users.
6. **Stable URLs; rename once, then 301.** Changing an image URL makes Google treat it as a new image; image recrawl is slow. If you rename, 301 the old URL to the new one ([SEJ – Mueller](https://www.searchenginejournal.com/google-changing-image-urls-will-affect-rankings-in-image-search/286163/), [GSQi – redirecting images](https://www.gsqi.com/marketing-blog/how-to-redirect-images-during-website-redesign-or-migration/)). The `/bilder/` URLs went live on 2026-10-05 → now is the cheapest moment to do the final move/rename in **one** step.
7. **Same-origin, crawlable `<img src>`**; images are not indexed from CSS backgrounds. Use `width`/`height`, `srcset` for responsive variants, lazy-load below the fold only ([Google Image SEO best practices](https://developers.google.com/search/docs/appearance/google-images)).
8. **Large previews:** at least 1200 px wide, > 300 000 px, ideally 16:9 (e.g. 1280×720 / 1600×900) plus `max-image-preview:large` for Discover/large thumbnails ([Google Discover docs](https://developers.google.com/search/docs/appearance/google-discover), [SEJ](https://www.searchenginejournal.com/google-discover-large-images-2/374555/)).
9. **Structured data images:** absolute, crawlable URLs; for Article/BlogPosting give several images in **16:9, 4:3 and 1:1**, each ≥ 50 000 px (w×h) ([Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article)).
10. **Image sitemap:** only `<image:image>` + `<image:loc>` still count; `caption`, `title`, `geo_location`, `license` were deprecated in Aug 2022 ([Google Search Central blog](https://developers.google.com/search/blog/2022/05/spring-cleaning-sitemap-extensions), [Image sitemaps](https://developers.google.com/search/docs/advanced/sitemaps/image-sitemaps)). Useful mainly for images Google might not discover (lightbox/gallery, JS-rendered).
11. **AI-generated images: keep/set IPTC `DigitalSourceType = trainedAlgorithmicMedia`.** Google reads it and can show "AI-generated / made with AI" in *About this image*; Google recommends it for generative images, and Merchant Center even requires it ([Google image metadata](https://developers.google.com/search/docs/appearance/structured-data/image-license-metadata), [IPTC quick guide](https://iptc.org/standards/photo-metadata/quick-guide-to-iptc-photo-metadata-and-google-images/), [Merchant Center AI content](https://support.google.com/merchants/answer/14743464), [SEJ](https://www.searchenginejournal.com/google-search-now-supports-labeling-ai-generated-or-manipulated-images/521675/)). Do not strip it when compressing (`convert -strip` removes it!). Google also asks to fact-check AI content before publishing ([Google gen-AI content guidance](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)).
12. **License metadata (`license`, `acquireLicensePage`, `creator`, `creditText`, `copyrightNotice`)** only buys the "Licensable" badge in Google Images; either IPTC or structured data is enough, structured data wins on conflict ([Google image metadata](https://developers.google.com/search/docs/appearance/structured-data/image-license-metadata)). Low value for a tour operator → optional; `creator`/`copyrightNotice` on **owner photos** is cheap and protects them.
13. **Real photos beat AI scenes for E-E-A-T.** For recognisable real places (Maya Bay, James Bond Island, Hong, Railay) a real trip photo ranks and converts better and is honest; the AI scenes are placeholders → replace step by step with owner photos (same file name, so no redirect needed).

## 3. Technical recommendations

### 3.1 Hosting, path and redirects
- Download all 22 Higgsfield files and serve them statically from `public/images/` (proposed names in the table). Reasons: no runtime dependency on the Higgsfield CloudFront CDN (the proxy returns 502 if it fails), one consistent folder, files can carry correct IPTC metadata, and responsive variants can be produced. `/images/` vs `/bilder/` has no ranking effect; consistency does.
- Then **301** `/bilder/<old-name>` → `/images/<new-name>` for all 22 (a tiny map; `src/routes/bilder.$file.ts` can become a redirect handler using `image-seo-plan.json`). Keep the redirects ≥ 1 year. Planned guide photos are not live → no redirect.
- Do the move + 4 renames in **one** deploy; afterwards never rename again – replace an AI picture with a real photo **under the same file name**.
- Docs `docs/images.md` suggest `convert -strip -quality 78`: use `-strip` only for owner photos (EXIF/GPS privacy) and then re-add IPTC creator/copyright; for AI files **keep** `DigitalSourceType` (or set it with `exiftool -XMP-iptcExt:DigitalSourceType="http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia"`).

### 3.2 Dimensions and formats
- Master width ≥ 1600 px (16:9 where the layout allows), WebP q≈75–80, plus a 900 px (cards) and a 1200×630 / 1600×900 JPG for `og:image`/JSON-LD. Current owner files: boat 1672×941 ✓, hero 1080×1312 (portrait, < 1200 px wide → not Discover-large; ask the owner for a ≥ 1600 px original or a 16:9 crop).
- Add `srcset`/`sizes` for local files (today `SmartImage` only builds srcset for Unsplash URLs) and explicit `width`/`height` to avoid CLS.
- `max-image-preview:large` in the robots meta of `/secret-islands` and guide pages (not found in the code).
- For each guide article provide 16:9, 4:3, 1:1 crops (e.g. `<name>-16x9.webp`, `-4x3`, `-1x1`) for BlogPosting `image`.

### 3.3 Structured data (`src/components/secret-islands/seo.ts`)
- **BlogPosting `image: [a.image]` is a relative path (`/bilder/...`)** → must be absolute (`SITE_URL + path`); better an array of the three crops (rule 9). TouristTrip already prefixes `SITE_URL` ✓.
- Optionally use `ImageObject` instead of plain URLs: `{ "@type":"ImageObject", url, width, height, caption: <alt in page language>, creator, copyrightNotice }` – `caption` repeats the alt, `width/height` lets Google pick the right image.
- TravelAgency: `logo` → square PNG ≥ 112×112 at a stable `/images/krabi-secret-islands-logo.png`; `image` → the real boat photo (keep).
- Licensing fields (`license`, `acquireLicensePage`): optional; only worth it if the owner wants the "Licensable" badge for own photos. Skip for AI images.
- AI labelling is done in the file (IPTC), not in JSON-LD; there is no schema.org property Google uses for it. Do not claim AI scenes as `creator: <owner>` photographs.

### 3.4 Image sitemap
- Add `xmlns:image="http://www.google.com/schemas/sitemap-image/1.1"` to `sitemap.xml` and, per `<url>`, `<image:image><image:loc>…</image:loc></image:image>` for the images actually shown on that page (landing: hero, boat, tour images, gallery; guide article: hero + gallery). Only `loc` – the other tags are deprecated.
- Use absolute final `/images/` URLs (not the redirected `/bilder/` ones).

### 3.5 og:image
- The PWA injector overwrites `og:*` (see `seo.ts` comment), so per-page share images only work where it doesn't run. Ensure the site-wide card is a Secret-Islands image (`krabi-secret-islands-privates-speedboat.jpg`, 1600×900), not the marketplace `og.jpg`, via the platform/project settings.
